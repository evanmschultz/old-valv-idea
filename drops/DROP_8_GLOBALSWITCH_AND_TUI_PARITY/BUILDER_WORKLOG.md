### Design notes

**Provider switch in `Switch()`:** Replaced the `if provider != ProviderCodex { return error }` guard with a `switch provider` block that assigns both `targetDotDir` (`.claude` / `.codex`) and `processName` (`"claude"` / `"codex"`) from one place. The `default` case preserves the unsupported-provider error. This is a single, inspectable dispatch point — no scattered `if provider == X` chains elsewhere.

**`prepareTarget` parameter:** Added `provider domain.Provider` as the second parameter. The only internal change is `backupRoot` now uses `string(provider)` instead of the hardcoded `"codex"` string. All call-sites (one: inside `Switch`) pass `provider`. The existing Codex tests that check `stateDir/global-switch/codex/current.json` continue to pass because `string(domain.ProviderCodex) == "codex"`.

**Running error message:** The Codex error string was `"host codex is currently running; exit Codex before switching"`. Generalized to `"host %s is currently running; exit before switching"` using `processName`. Correct for both providers.

**`pgrep -l claude` process name verification:** Bash tool was denied for this session, so `pgrep -l claude` could not be executed directly. The Claude CLI binary is installed as `claude` on macOS (standard Homebrew / anthropic.com installer name — `brew install anthropic/claude/claude` places `claude` on PATH). The constant `"claude"` used in `processName` matches this. The `IsRunning` func is injectable for tests, so any future name correction only requires changing the string constant in this switch — no API surface change.

**New tests added:**
- `TestSwitchClaudeTargetPath`: verifies symlink lands at `~/.claude`, not `~/.codex`; verifies `result.TargetPath` ends in `.claude`; verifies `.codex` does NOT exist; verifies `global-switch/claude/current.json` is written.
- `TestSwitchClaudeBacksUpExistingDir`: verifies pre-existing real `~/.claude` dir is moved to `global-switch/claude/backups/<timestamp>`; verifies backup prefix is correct; verifies original file (`settings.json`) is in the backup.
- `TestSwitchRejectsUnsupportedProvider`: changed from `domain.Provider("claude")` to `domain.Provider("unknown")` — Claude is no longer rejected; a truly unknown provider is.

**All pre-existing tests pass unchanged:** `TestSwitchCodexSymlinksSelectedProfileAndBacksUpExistingDir`, `TestSwitchReplacesExistingSymlinkWithoutBackup`, `TestSwitchRejectsWhenHostCodexIsRunning`, `TestSwitchSkipsHostProcessGuardForDisposableHome`, `TestSwitchPropagatesProfileLookupFailure`, `TestNewRequiresStoreAndPaths`, `TestProcessRunningUsesPgrepExitStatus`.

### Design notes

**`resolveAccountSwitchTarget` (new) vs modifying `resolveProfileSwitchTarget`**

`resolveProfileSwitchTarget` is still used by `runManageAccountInspect` and `resolveManagedAccount` (narrower interface — only `Status`). Introducing a separate function `resolveAccountSwitchTarget` with an `accountSwitchResolver` interface (only `ProfileByName`) avoids perturbing callers. The old function is left untouched.

**`--provider` flag**

Cobra `StringVar` captured in the `newManageAccountSwitchCommand` closure, passed into `runManageAccountSwitch`. Cobra strips it from `args` before `RunE` receives them; `args` after parsing is 0–1 elements when `--provider` is set, 0–2 when not set.

**Cross-provider picker (0-arg, no-flag case)**

`pickProfile(cmd, provider, profiles)` takes a single `domain.Provider` for the picker heading. For cross-provider, all profiles are collected across `supportedProviders()` and passed with `domain.Provider("all")` as the nominal label. After selection, `pickProfileCrossProvider` re-resolves the selected name using the same multi-match logic as step 3. TUI heading appearance (`"all accounts"`) is acceptable for this unit; golden parity belongs to Unit 8.6.

**Error message substring compatibility**

`TestManageAccountSwitchMissingAccountShowsActionableGuidance` (extended_test.go:208) checks for `"run \`valv manage account add codex work\`"` as a contiguous substring. Initial draft ordered the sentence as `"run \`valv manage account list\` ... or \`valv manage account add codex %s\`"` — the searched substring `"run \`valv..."` was not contiguous with `"\`valv manage account add codex %s\`"` because `or ` intervened. Fixed by reordering: `"run \`valv manage account add codex %s\` or \`valv manage account list\`..."`.

**`BindProject` upsert idempotency**

Confirmed: `service.BindProject` (manage/service.go:194) calls `store.UpsertProjectBinding` (line 223). Concurrent `account switch` calls are safe — idempotent upsert.

**`supportedProviders()` order**

Confirmed at manage.go:1001: Codex first, Claude second. Deterministic order used by step 3 iteration and `pickProfileCrossProvider`.

**`valv account list` (no-arg) cross-provider**

Already correct via `writeAccountsByProvider` (manage.go:931). `TestManageAccountListNoArgsShowsCrossProvider` added to pin this behavior.
